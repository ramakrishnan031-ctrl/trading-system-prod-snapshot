# SEEDING — WHAT THE LAYOUT MEASUREMENTS WERE TAKEN AGAINST

**Created 19-Aug-2026 (Rama Q4 = "C now, A later"). Documentation only.**
⛔ This phase promotes **no** harness into the repo and adds **no** CI gating. Option **A**
(harness into `ops_dashboard/qa/` with a seeded fixture per screen) remains planned work.

## WHY THIS FILE EXISTS

A layout measurement taken against an **empty** table and one taken against a **populated**
one produce the same number — `0` horizontal overflow — for opposite reasons. Screen 10 proved
it: its *"0 overflow"* reading was recorded while `trade_slippage_log` was empty, and a **5px
page overflow** appeared the moment the table was seeded.

⇒ 🔑 **A layout result without its seeding is not a result.** This file records the seeding, so
a later reader can tell a real zero from a vacuous one.

## ⛔ WHAT CANNOT BE RECONSTRUCTED — STATED FIRST, BECAUSE IT IS THE POINT

The claim *"page-level horizontal overflow = 0 across all 21 authenticated screens at
1920×1080 and 1440×900"* (closure pass `4ee1443`, 19-Aug) was produced by a **session-scratchpad
harness that is not in the repo** — a repo-wide grep for `serve_verify`, `virtual-time-budget`,
`--screenshot` and `window-size` returns **0 hits**.

⛔ **Its per-screen seeding was never recorded and cannot now be recovered.** Only one screen's
seeding is known, because it was written down after the fact: **Screen 10** was re-measured with
`trade_slippage_log` seeded, which is how the vacuous zero was caught.

⇒ ⚠️ **For the other 20 screens the evidence does not distinguish a real zero from S10's
pre-seeding zero.** ⛔ That is **not** a claim they are wrong — it is a claim that they are
**unverified**, and it is why Option A matters.

### ⭐ THE RATIO, ⛔ NOT MERELY THE SHAPE
`system_metrics` was seeded to the **measured production ratio**, ⛔ not to "some rows":
**`disk_used_pct` REAL, `cpu_pct` and `memory_mb` = `-1.0` sentinels.**
Read-only from the VM on 19-Aug: **3,651 rows, 3,069 with a real `disk_used_pct`, 0 real
`cpu_pct`, 0 real `memory_mb`**, and **all 60** rows in the read window real.
⇒ the API returns `disk measured n=60` with `cpu` / `ram` / `response_time` empty — **exactly
production**, where only the **Disk** tab renders a chart. ⛔ A balanced fixture would have
rendered four charts and measured a screen that does not exist.

### ⚠️ AND A PRODUCTION-SHAPED FIXTURE STILL WAS NOT ENOUGH
The S09 gutter passed at **58px** against the fixture's own `~₹200` ticks and still **clipped the
artwork's widest tick `-₹40,000` by 0.08px** (50.08px measured against the 50px it leaves).
⇒ 🔑 **Seeding to production shape does not cover an ARTWORK worst case that production has not
yet produced.** The worst-case label had to be **rendered and measured** directly. Gutter is
**64px**.

## HOW THE MEASUREMENTS WERE TAKEN
Headless Edge (`--headless=new --hide-scrollbars --virtual-time-budget --dump-dom`) at
**1920×1080** and **1440×900**; a probe injected into the page writes JSON into `#__probe`.
- SVG text: **`getScreenCTM()`** — exact, and it honours `preserveAspectRatio`.
- HTML overlay labels: `getBoundingClientRect()` + computed `font-size`.
- Overflow: `documentElement`/`body` `scrollWidth` vs `clientWidth`.
📌 ⛔ **The probe initially measured only SVG text and sub-13px HTML, so it could not see the S09
overlay labels at all** (HTML, exactly 13px — in neither set). It was extended before any S09
claim was made.
