# Cron Daily Report Fix - 2026-05-18

## Issue
Daily report cron job (16:05 IST) failed with `ModuleNotFoundError: No module named 'reports'`

## Root Cause
**Broken cron entry** (ran script directly without setting working directory):
```bash
5 16 * * 1-5 /home/ubuntu/systems/venv/bin/python /home/ubuntu/systems/trading-system/reports/daily_report.py >> /home/ubuntu/systems/trading-system/logs/daily_report.log 2>&1
```

**Why it failed**: 
- Python couldn't resolve relative imports (`from reports.style_constants import ...`)
- Working directory wasn't set to project root
- PYTHONPATH didn't include project directory

## Fix Applied
**Updated cron entry** (cd to project root + run as module):
```bash
5 16 * * 1-5 cd /home/ubuntu/systems/trading-system && /home/ubuntu/systems/venv/bin/python -m reports.daily_report >> logs/daily_report.log 2>&1
```

**Changes**:
1. Added `cd /home/ubuntu/systems/trading-system &&` to set working directory
2. Changed `/path/to/script.py` → `-m reports.daily_report` to run as module
3. Changed absolute log path → relative `logs/` (since we cd first)

## Lessons Learned
1. **Always cd to project root** when running Python modules with relative imports
2. **Use `-m module.name`** instead of direct script paths for proper module resolution
3. **Test cron commands manually** before deploying: copy the exact command from crontab and run it
4. **Pattern consistency**: All Python cron jobs should follow the same format:
   ```bash
   cd /home/ubuntu/systems/trading-system && /home/ubuntu/systems/venv/bin/python -m module.name >> logs/logfile.log 2>&1
   ```
