AUDIT 1 - "Pre-live audit" (10 high-level concerns)
================================================================

# 1. State consistency risk (BIGGEST ISSUE)
Not strong guarantee: Order placement + state update = ATOMIC
Risk: order placed OK, DB update fails -> system loses track.
Fix: transaction(reserve, insert trade, insert order, COMMIT)
THEN place broker order. Reconciliation must fix mismatch.

# 2. Broker failure handling incomplete
zerodha_adapter.py, order_monitor.py likely don't fully handle:
- partial fills
- delayed fills
- rejected SL
- network retry edge cases
Missing: IF order status unknown -> reconcile immediately.
IF SL missing -> HALT SYSTEM.

# 3. Reconciliation robustness unclear
6-case reconciliation (G1) especially:
- orphan broker position
- partial quantity mismatch
- orphan open orders
Non-negotiable for live. Weak -> lose money silently.

# 4. Crash recovery risk
On restart: rebuild state ONLY from broker?
Required: Broker = source of truth ALWAYS.

# 5. Concurrency + SQLite risk
Multi-thread + SQLite. Risks: multiple writes, long
transactions, deadlocks.
Must verify: WAL mode ON, short transactions, no nested
transactions.

# 6. Order lifecycle correctness
Does order_state_machine enforce: Only ONE exit path
(SL OR TGT never both)?
If not: Double execution = loss.

# 7. Kill switch enforcement
ALL modules respect it BEFORE action?
Especially order placement + signal processing.

# 8. Signal dedup (P6) enforcement
Must be enforced at DB level (UNIQUE index).
Only in Python -> race condition -> duplicate trades.

# 9. Logging + traceability
Every log must include signal_id, trade_id, order_id.

# 10. No chaos testing yet
Haven't tested:
- broker API failure
- network timeout
- partial fills
- restart mid-trade

Minimum test checklist before live:
1. Order flow: entry success, entry reject, partial fill,
   timeout cancel
2. Exit flow: SL hit, TGT hit, cancel failure
3. Crash scenarios: crash after entry, crash before SL,
   restart recovery
4. Reconciliation: manual close in broker, orphan order,
   mismatch qty
5. Capital: multiple trades, loss sequence, T+1 behavior

Medium issues: EventBus usage minimal (G9), Config validation
fail-fast, Rate limiter per endpoint, CRITICAL alerts always
delivered.

DO NOT go live yet. Paper trade 5-7 days -> inject failures
manually -> fix inconsistencies -> live with small capital only.

AUDIT 2 - "Second pass" (30 concrete issues)
================================================================

CRITICAL:

# 1. State consistency (repeated from Audit 1)

# 2. Race condition in order_placer.py line 147-151:
fill_map accessed without lock in _on_order_filled.
_fill_map written in place() with lock, but _on_order_filled
runs in order_monitor thread -> race with place() completion.
Window small but exists.

# 3. Incomplete ATR/Sector Implementation:
step_executor returns 0.5 for missing sector/ATR (neutral
score). _derive_prices warns but falls back to FIXED_PCT for
ATR. DANGEROUS - ATR strategies silently degrade without alert.

# 4. Missing Quote Provider in Paper Mode:
zerodha_adapter.py requires quote_provider for paper mode
get_quote(). main.py does NOT inject a quote provider. Paper
mode get_quote() will raise NotImplementedError and crash.

# 5. StateStore Schema Version Mismatch Risk:
EXPECTED_SCHEMA_VERSION = 8. No migration logic. If old DB
exists, startup crashes with SchemaVersionMismatch.

# 6. Missing quote_fn for SmartTgtManager:
main.py passes broker_adapter.get_quote. quote_fn required for
startup LTP check; if missing, only warning logged.

# 7. OrderMonitor on_orphan_callback Type Mismatch:
_make_orphan_cb calls kill_switch.soft_kill() missing
triggered_by parameter.

# 8. _make_critical_failure_cb Same Issue:
Returns _on_critical_failure(source, reason) but
kill_switch.soft_kill() needs triggered_by.

# 9. WebhookReceiver in_flight Symbol Never Released on Some
Paths:
signal_processor releases in finally block (good). But if
signal_processor crashes before finally, symbol stuck in
in_flight. No timeout mechanism.

# 10. Missing order_reconciler.broker_orders_fn:
main.py passes None. CHECK 6 (ORPHAN_ORDER) will never run.
Open orders not reconciled.

HIGH SEVERITY:

# 11. Telegram Paper Mode Sends Real Alerts:
TelegramNotifier paper mode should log only, but main.py
uses real TELEGRAM_BOT_TOKEN. Paper mode will send real
Telegram messages.

# 12. Missing sector_lookup_fn Implementation:
risk_engine uses sector_lookup_fn but main.py passes lambda
returning "UNKNOWN". All symbols get UNKNOWN, sector exposure
check useless.

# 13. CandleStore Never Started:
main.py creates CandleStore and registers callbacks but never
calls start(). LiveFeedManager will push ticks but candles
never close.

# 14. SmartTgtManager Never Started:
main.py creates and calls start() (OK). start() re-registers
callback (idempotent, fine). But main.py does NOT wire
on_reconnect callback from candle_store to smart_tgt properly.

# 15. Missing OrderMonitor.track() Calls for LimitTripleProtocol
Orders:
order_placer tracks only entry order. SL and TGT orders not
tracked by OrderMonitor. If SL order fails to fill, no
timeout/cancellation.

# 16. EodSquareoff Race on _fired_for_date:
check_and_fire() sets _fired_for_date[today] = True BEFORE
_fire(). If _fire() raises, flag is already set - EOD won't
retry. Should set flag only after successful fire.

# 17. DailyReviewGenerator Missing openpyxl Import Handling:
_write_xlsx() imports openpyxl inside method. If not installed,
crashes at report time (not startup).

# 18. preflight_scanner_check.py Uses requests but Not in
Requirements:
Assumes requests is installed. Should use urllib like rest
of system or document dependency.

# 19. alert_watcher.py Imports alerts.critical - File Not
Provided:
Module references alerts/critical.py which was not in
submission. Critical alerts may not work.
[NOTE: Actually built in Module 24. Verify existence.]

# 20. Missing core/ids.py Validation in WebhookReceiver:
new_signal_id() called but no validation that signal_id is
unique before insert. SQLite PRIMARY KEY catches duplicates
but error handling present.

MEDIUM SEVERITY:

# 21. Logging Directory Hardcoded to logs/:
No rotation policy. Logs will grow indefinitely. No cleanup
of old log files.

# 22. No Daily P&L Reset in fund_manager:
reset_daily_pnl() exists but never called by main.py.
EodSquareoff should call it after square-off.

# 23. market_windows.py Uses Hardcoded _NEXT_DAY_LOOKAHEAD_CAP
= 10:
If holidays config has 11 consecutive holidays, raises
ValueError. Unlikely for NSE but possible.

# 24. Missing instrument_token Mapping for CandleStore:
LiveFeedManager passes ticks with instrument_token.
CandleStore needs symbol mapping but set_token_map() never
called in main.py.

# 25. LiveFeedManager Callback Signature Mismatch:
register_callback(lambda ticks: [candle_store.on_tick(t)
for t in ticks]). candle_store.on_tick() expects
(instrument_token, ltp, ts) but receives a dict.
WILL CRASH ON FIRST TICK.

LOW SEVERITY / NITPICKS:

# 26. main.py line 68: _log: logging.Logger defined but
reassigned after setup_logging() - confusing

# 27. product_resolver.py - BRACKET_ORDER maps to empty string,
but no runtime check in order placement

# 28. cost_calculator.py - stamp_duty_cnc_buy_pct in YAML but
hardcoded to 0.015 in code? (needs verification)

# 29. rate_limiter.py - _seconds_until_ready() uses
self._frozen_until but doesn't account for rate refill during
freeze correctly

# 30. order_state_machine.py - No persistence means crash loses
all in-flight order states (reconciler recovers, but still a gap)

WHAT WORKS WELL (no changes needed):
- Exception hierarchy comprehensive
- StateStore with transaction context manager solid
- FundManager invariant checks excellent
- KillSwitch with RLock fixes deadlock
- EventBus collect-all-errors pattern correct
- Token bucket rate limiter sound
- OrderStateMachine transition table complete
- ProductResolver abstraction clean
- Configuration loading with Pydantic robust
- TimeAuthority with skew detection well-implemented

AUDIT 3 - "Final thorough pass" (19 additional, 54 total)
================================================================

CRITICAL NEW:

# 1. main.py Line 353 - KiteClient Building with Hardcoded
Exchange:
kite = KiteConnect(api_key=..., set_access_token(...)). No
timeout configuration passed. Adapter expects read_sec from
broker_limits.yaml but never applies it to client.
Fix: KiteConnect(api_key=..., timeout=...,
connect_timeout=...).

# 2. order_monitor.py - No Handling for get_order_history()
Empty Response (Line 214):
if not history: return (silently skips order). Order stays
in watch list forever, never times out.
Fix: Treat as orphan after N consecutive empty responses.

# 3. signal_processor.py - continue_from_gate() Uses Wrong
side Parameter (Line 469):
self._placer.place(symbol=symbol, side=direction, ...)
direction is "LONG"/"SHORT", placer expects "BUY"/"SELL".
WILL CRASH on gate-released signals.

# 4. main.py - EntryGate Created Before signal_processor.start():
EntryGate is created but its on_release callback calls
signal_processor.continue_from_gate(). If gate releases before
signal_processor starts, callback on uninitialized processor.
Fix: Start signal_processor BEFORE entry_gate.

# 5. order_reconciler.py - _check1_manual_close() References
Missing Field (Line 325):
product = trade["product"] - trade dict from
get_all_open_trades() doesn't have 'product'. _PRODUCT_TO_INTENT
lookup will fail, capital release skipped.

HIGH SEVERITY NEW:

# 6. live_feed.py - No Reconnection to candle_store After
Broker Disconnect (Line 195):
_on_reconnect calls candle_store callback. But
smart_tgt_manager.on_reconnect() is NOT called because
callback only notifies candle_store.
Issue: main.py line ~395 sets callback to tuple
(candle_store.mark_reconnect, smart_tgt.on_reconnect) but
live_feed expects single callable, not tuple.

# 7. telegram_notifier.py Not Provided - Cannot Verify:
Cannot verify rate limiting on Telegram API, retry logic,
queue overflow handling, paper mode suppression.
[NOTE: Actually built in Module 24. Verify existence.]

# 8. startup_checks.py - check_clock_skew() Uses Hardcoded
Tolerance 30.0 (Line 298):
Ignores app_config.system.clock.startup_max_skew_sec from
config.

# 9. eod_squareoff.py - _cancel_pending_entries() Doesn't
Update Order Status:
After cancelling order, updates trade status to CANCELLED
but does NOT update order row status. Order stays PENDING
in DB, causing reconciler confusion.

# 10. webhook_receiver.py - No Retry on queue.Full:
When queue full, marks signal as QUEUE_FULL and returns 200
(success). Client thinks signal was accepted but it was
dropped. Should return 503.

MEDIUM SEVERITY NEW:

# 11. signal_processor.py - _derive_prices() Can Return
Negative Prices:
if direction == "LONG": entry_price = trigger_price * (1.0 -
offset). offset could be > 1.0. No validation entry_price > 0.
If entry_offset_pct > 1.0, entry_price becomes negative.

# 12. order_placer.py - _persist_entry_orders() Uses
Hardcoded Product "MIS":
product = "MIS" if intent == "INTRADAY" else "CNC".
Ignores product_resolver and product_map for order persistence.
CNC orders will have wrong product code in DB.

# 13. position_sizer.py - sl_distance Can Be Zero:
sl_distance = abs(entry_price - sl_price). If entry == sl,
division by zero later. Validation checks sl_price != entry
but only warns, doesn't reject.

# 14. risk_engine.py - snapshot Missing from ApprovalResult
on Rejection Path:
When returning early for rejection, snapshot dict may be
incomplete (only fields computed up to that point). Docstring
promises all 9 fields always.

# 15. state_store.py - get_session_row() Returns None on
First Run:
Fine, but detect_startup_scenario() treats as COLD. However,
session.last_config_hash is None so check_config_hash()
returns changed=False (good). But _write_session() in main.py
writes row after startup, not before.

LOW SEVERITY / NITPICKS NEW:

# 16. main.py line 438: KillSwitch.resume() called with
resumed_by="operator" but no check that args.resume was
actually passed. Should validate.

# 17. zerodha_adapter.py - get_quote() in paper mode requires
quote_provider, but error message doesn't tell operator how
to fix.

# 18. order_protocol_co.py - Returns success=True even when
TGT placement fails. Caller may think full placement succeeded.

# 19. smart_tgt_manager.py - _MAX_CONSECUTIVE_FAILURES = 3
hardcoded. Should be configurable.

# 20. candle_store.py - MAX_HISTORY = 390 assumes 6.5 hours
* 60 minutes. On expiry days (market closes early), holds
less than full day.
