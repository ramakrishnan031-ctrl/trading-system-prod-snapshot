CONCERN 4: CRITICAL GAP — Multi-inning stock tracking
================================================================

This is the MOST important gap you identified. Analysis:

What the current system does:
  - Places ONE entry order per signal
  - Monitors its fills
  - Marks trade CLOSED when SL or TGT hits
  - That's it. Stock price after CLOSED is ignored.

Your requirement:
  After original entry (actual broker order placed on signal):
    INNING 1: actual trade entry -> actual SL or TGT hit
    INNING 2: from inning-1 exit price, simulate re-entry
              at same price, track to next SL/TGT (no real
              broker order)
    INNING 3: same from inning-2 exit
  Up to 3 innings tracked. Telegram and reports show ALL
  innings, not just the first one.

This is a POWERFUL backtesting/analysis feature. Protects
against the bug you described: "exited at SL, then price
recovered to TGT — report falsely claims TGT hit".

This was NOT in locked_decisions.yaml. It's a NEW capability.

PROPOSED MODULE 38 (before paper trial):
  orders/shadow_tracker.py

  Purpose: After a trade closes (real exit at SL/TGT),
  continue tracking the same symbol for up to 3 "innings"
  using simulated entries at the original SL/TGT price.
  No real broker orders. Pure price monitoring.

LOCK (ST-NEW1 to ST-NEW12):

ST-NEW1 — Inning data model:
  Inning dataclass:
    inning_number: int (1, 2, or 3)
    trade_id: str (links to original trade)
    entry_price: float (actual for inning 1;
                        = previous inning's exit price for 2+)
    entry_ts: datetime
    sl_price: float
    tgt_price: float
    direction: str (LONG | SHORT)
    exit_price: float | None
    exit_ts: datetime | None
    exit_reason: str | None (SL | TGT | EOD | STILL_OPEN)
    is_real: bool (True for inning 1, False for 2+)

ST-NEW2 — shadow_tracker registers on PositionClosed event:
  Subscribe to PositionClosed event bus type.
  When fires: check if trade has < 3 innings.
  If yes and within market hours:
    Start inning 2 simulated:
      entry_price = exit_price of inning 1
      sl/tgt computed from strategy (same rules as original)
      Register with live_feed LTP updates for this symbol
      Track until SL or TGT hit OR market close (15:30)

ST-NEW3 — Rules:
  - SL hit -> close inning, start next one at same price
  - TGT hit -> close inning, start next one at same price
  - Market close (15:30) -> close inning with
    exit_reason=EOD, stop tracking
  - Already 3 innings recorded -> stop tracking
  - Symbol's original trade had direction X -> all innings
    keep direction X (LONG stays LONG)

ST-NEW4 — Telegram alerts:
  Per inning close: send INFO alert with:
    Symbol, direction, inning #, entry, exit, P&L %,
    real/simulated tag
  Final alert when all 3 innings done or EOD:
    Summary of all innings for this trade.

ST-NEW5 — Persistence:
  Add innings table to state_store:
    id, trade_id, inning_number, entry_price, entry_ts,
    sl_price, tgt_price, direction, exit_price, exit_ts,
    exit_reason, is_real
  Query helpers:
    get_innings_for_trade(trade_id) -> list[Inning]
    get_innings_for_date(date_iso) -> list[Inning]

ST-NEW6 — Daily report integration:
  Add new sheet/section: MULTI_INNING_ANALYSIS
    For each trade that had innings: show all 3 (or fewer)
    with real vs simulated flag and P&L.
  Update SUMMARY sheet: "Total innings tracked", "Simulated
  tgt hits", etc.

ST-NEW7 — Layer & deps:
