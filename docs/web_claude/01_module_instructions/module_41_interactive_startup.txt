MODULE 41: Interactive Startup + Zerodha Login Flow
================================================================

Rama's decisions (locked):

A. Token method: Browser-assisted (user opens Kite URL, logs in,
   pastes request_token). Ported from old system's
   auth/zerodha_login.py. NO selenium/playwright/TOTP automation
   for v2. Operator's manual step, 5 min max.

B. accounts.csv schema: Add paper_capital column. Final schema:
   account_id, broker, label, is_primary,
   api_key_env, api_secret_env, totp_secret_env,
   paper_capital, capital_share_pct, enabled

C. paper_capital: 5,000,000 INR for each account.
   Live mode: ignored (syncs from broker).
   Paper mode: used as starting balance.

D. Design: Single main.py with --interactive flag.
   Interactive = PC operator session.
   Non-interactive (default) = VM systemd-driven.

E. Token file format: account_id + broker + access_token +
   date + saved_at. Enhanced with expires_at field.

F. VM vs PC:
   VM paper: headless via systemd (no prompt, uses primary)
   VM live: SSH in, run `python main.py --interactive --mode live`
            to get the prompt. Once started, runs headless.
   PC: always interactive during paper trial.

Pre-flight ordering (Rama's refinement):
   1. Holiday/weekend check FIRST. If not trading day: clean
      exit, NO logs, NO further checks, NO threads.
   2. Then: system health, config, scanners, chartink sync.

Step 3 enhancement: Pre-fill username/client_id in login URL
so operator types only password + TOTP.

SU9 — Interactive Step 3: Check Existing Token

  Path: data_store/session/zerodha_token.json

  If file exists AND token.account_id == selected AND
     token.date == today:
    Valid token exists.
    Ask: "Use existing token? [Y/n]:"
    Default Y -> skip to Step 4.
    N -> proceed to login flow.

  If file missing OR token.account_id != selected OR
     token.date != today:
    Proceed to login flow (SU10).

  If token.account_id != selected:
    Warn loudly:
      "!! Token file belongs to different account ({token.account_id}) !!"
      "!! Selected: {selected} !!"
      "!! Re-login required. !!"

SU10 — Interactive Step 3b: Login Flow (browser-assisted)

  Port from old system auth/zerodha_login.py with these
  enhancements:

  a. Resolve credentials:
       api_key = os.environ[row.api_key_env]
       api_secret = os.environ[row.api_secret_env]
     If either missing: exit with error naming the env var.

  b. Load client_id from accounts.csv.
     NOTE: current v2 schema does NOT have client_id column.
     Add a column OR source it from a new file.
     Recommended: Rama provides client_id per account via
     env var named in a new column: client_id_env.
     For now: skip client_id pre-fill if not available.

     IF Rama adds client_id column: pre-fill in URL via
     query params (Kite supports user_id= param in some
     login paths). Test if this actually works with Kite.
     If not: just skip pre-fill, operator types login.

  c. Build login URL:
       https://kite.zerodha.com/connect/login?v=3&api_key={api_key}

     (Kite doesn't have a public param for pre-filling user_id.
      Pre-fill idea is nice but not natively supported. Rama's
      ask #3.iii is actually not possible without customizing
      Zerodha's login page. DOCUMENT this limitation.)

  d. Open browser: webbrowser.open(login_url)

  e. Prompt:
       "Complete login in browser."
       "After login, Zerodha redirects to localhost URL."
       "Example: http://127.0.0.1/?request_token=ABC...&action=login"
       ""
       "Paste request_token here: "

  f. Validate input non-empty, re-prompt if blank.

  g. Exchange request_token -> access_token:
       checksum = sha256(api_key + request_token + api_secret)
       POST https://api.kite.trade/session/token
         data: {api_key, request_token, checksum}
       -> access_token

  h. Save to data_store/session/zerodha_token.json:
       {
         "account_id": "LFL836",
         "broker": "zerodha",
         "access_token": "<token>",
         "api_key": "<for mismatch detect>",
         "date": "2026-04-17",
         "saved_at": "2026-04-17T08:45:12+05:30",
         "expires_at": "2026-04-18T05:00:00+05:30"
       }

  i. Print success + path.

  j. Optional: offer to run copy_token_to_vm.bat if
     system detects it's on Windows and the .bat exists.
