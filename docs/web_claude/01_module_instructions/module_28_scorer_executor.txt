28a — screening/quality_scorer.py (QS1-QS10)
================================================================

QS1 — Purpose: Compute a quality score (0-100) for a signal
  based on weighted step scores. Returns score + tier.
  Thin wrapper around scoring_weights.yaml. NO inline
  constants (P9b). Audit: complete rewrite (4 syntax errors
  + 1 logic error in original).

QS2 — Constructor:
  QualityScorer(
    weights: ScoringWeightsConfig,  # from config_loader
    logger,
  )
  weights is the Pydantic model from config_loader covering
  scoring_weights.yaml (already loaded as part of AppConfig).

QS3 — Public API:
  scorer.score(step_results: dict[str, float]) -> ScoreResult

  step_results: dict mapping step_name -> raw score (0.0-1.0).
    Step names must match scoring_weights.yaml keys:
    volume_surge, vwap_position, atr_filter, rsi_range,
    price_action, sector_strength, time_of_day, spread_check,
    circuit_check, signal_age.
  If a step is missing from step_results: treated as 0.0
  (log WARNING with missing step name).

  ScoreResult (frozen dataclass):
    total_score: int         # 0-100
    tier: str                # "HIGH" | "MEDIUM" | "LOW"
    passed: bool             # total_score >= min_pass_score
    step_scores: dict[str, int]  # weighted score per step
    missing_steps: list[str]     # steps not in step_results
    min_pass_score: int          # from config
    tier_thresholds: dict        # from config

QS4 — Scoring formula:
  For each step:
    weighted_score = raw_score * step_weight
  total = sum(all weighted_scores)
  total capped at 100.

QS5 — Tier assignment:
  total >= high_score_threshold  -> "HIGH"
  total >= medium_score_threshold -> "MEDIUM"
  else -> "LOW"
  Thresholds from scoring_weights.yaml (already loaded:
  high=80, medium=65).

QS6 — Audit Bug 3 fix (priority_score used addition):
  Original used addition for priority ranking. V2 uses
  multiplication is NOT applicable here (that was a different
  function). QS4 formula is correct (weighted sum).
  This is documented to prevent confusion.

QS7 — Audit Bug 5 fix (LOW tier gets full size):
  position_sizer already handles tier multipliers (PS5).
  Scorer returns the tier string. Sizer applies the multiplier.
  Scorer does NOT apply multipliers. Clean separation.

QS8 — Layer & deps:
  Layer 4 (screening/). Imports: stdlib (dataclasses),
  core.config_loader (ScoringWeightsConfig type),
  core.logger. NO state_store, NO broker.

QS9 — Determinism:
  Same step_results + same config -> same ScoreResult.
  Pure function. Thread-safe.

QS10 — NOT in scope:
  - Computing raw step scores (step_executor does that)
  - Rejecting signals (secondary_screener decides)
  - Per-strategy score overrides (strategy.min_score overrides
    happen in secondary_screener, not here)

28b — screening/step_executor.py (SE1-SE10)
================================================================

SE1 — Purpose: Execute individual screening steps. Each step
  is a pure function that takes signal data + market data and
  returns a raw score (0.0-1.0). step_executor runs all 10
  steps, captures exceptions, returns step_results dict.

SE2 — Constructor:
  StepExecutor(
    logger,
  )
  Stateless. No config dependency (thresholds injected per
  call from strategy config or screening config).

SE3 — Public API:
  executor.run_all(
    signal: dict,        # {symbol, scanner_name, trigger_price,
                         #  triggered_at, direction, intent}
    market_data: dict,   # {ltp, volume, vwap, atr, rsi,
                         #  bid, ask, sector, circuit_state,
                         #  day_high, day_low, prev_close,
                         #  avg_volume_20d}
    thresholds: dict,    # per-strategy thresholds from
                         # StrategyConfig (min_volume_surge,
                         # min_adr_pct, max_spread_pct)
  ) -> StepExecutorResult

  StepExecutorResult (frozen dataclass):
    step_results: dict[str, float]  # step_name -> 0.0-1.0
    step_statuses: dict[str, str]   # step_name -> PASSED|REJECTED|ERROR
    rejected_at: str | None         # first step that returned 0.0
    error_steps: list[str]          # steps that raised exceptions
    latencies_ms: dict[str, float]  # per-step timing (P9a add)

SE4 — The 10 steps (lock names + logic summary):

  step_1_volume_surge:
    score = 1.0 if volume > avg_volume_20d * min_volume_surge
    score = 0.0 otherwise
    Audit fix (c): if avg_volume_20d missing or 0 -> 0.0
    (REJECTED_INSUFFICIENT_DATA, not "allow through")

  step_2_vwap_position:
    LONG: score = 1.0 if ltp > vwap
    SHORT: score = 1.0 if ltp < vwap
    Audit fix (b): direction-aware

  step_3_atr_filter:
    adr_pct = atr / ltp * 100
    score = 1.0 if adr_pct >= min_adr_pct
    If atr missing or 0 -> 0.0

  step_4_rsi_range:
    LONG: score = 1.0 if 40 <= rsi <= 80
    SHORT: score = 1.0 if 20 <= rsi <= 60
    If rsi missing -> 0.5 (neutral, don't penalize)

  step_5_price_action:
    body_pct = abs(ltp - open) / (day_high - day_low + 1e-9)
    score = min(1.0, body_pct * 2)
    Rewards strong directional candle bodies.

  step_6_sector_strength:
    score = 1.0 if sector provided (placeholder — real
    sector strength calculation deferred to v2.1)
    score = 0.5 if sector missing

  step_7_time_of_day:
    minutes_since_open = (now - 09:15).minutes
    if minutes_since_open < 15: score = 0.5 (too early)
    if minutes_since_open < 60: score = 1.0 (prime)
    if minutes_since_open < 180: score = 0.8 (good)
    else: score = 0.5 (afternoon)

  step_8_spread_check:
    spread_pct = (ask - bid) / ltp * 100
    score = 1.0 if spread_pct <= max_spread_pct
    score = 0.0 otherwise
    If bid/ask missing -> 0.5 (neutral)

  step_9_circuit_check:
    score = 0.0 if circuit_state in ("upper_circuit",
            "lower_circuit") (P9a add)
    score = 1.0 otherwise

  step_10_signal_age:
    age_sec = (now - triggered_at).total_seconds()
    score = 1.0 if age_sec <= 30
    score = 0.5 if age_sec <= 60
    score = 0.0 if age_sec > 90 (P9a add: >90s reject)

SE5 — Exception handling per step (P9a fix a):
  Each step wrapped in try/except. On exception:
    step_results[name] = 0.0
    step_statuses[name] = "ERROR"
    error_steps.append(name)
    Log ERROR with step name + traceback
  Audit fix: NO silent continue. Error recorded explicitly.
  run_all() does NOT raise — returns all results including
  errors. Caller (secondary_screener) decides to reject.

SE6 — Per-step latency tracking (P9a add):
  Each step timed with time.monotonic().
  latencies_ms[step_name] = elapsed_ms.
  Logged at DEBUG level per step.

SE7 — Short-circuit option:
  run_all() runs ALL 10 steps always (no short-circuit).
  Rationale: quality_scorer needs all 10 scores for weighted
  total. Short-circuit would undercount.
  If caller wants early rejection: check step_statuses after.

SE8 — market_data contract (what caller must provide):
  Keys: ltp, volume, vwap, atr, rsi, bid, ask, sector,
        circuit_state, day_high, day_low, prev_close,
        avg_volume_20d, open (today's open).
  Missing keys: step uses default (0.5 neutral or 0.0 reject,
  per step definition above). NEVER raise on missing key.

SE9 — Layer & deps:
  Layer 4 (screening/). Imports: stdlib (time, datetime,
  dataclasses), core.logger, core.time_authority.
  NO config_loader, NO state_store, NO broker.

SE10 — Determinism:
  Same signal + same market_data + same thresholds + same
  now_ist -> same result. Pure except for now_ist dependency
  (injected or from time_authority).
