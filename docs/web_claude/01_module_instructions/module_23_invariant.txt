================================================================
MODULE-SPECIFIC LOCK (INV1-INV10)
================================================================

INV1 — Purpose: Pure stateless assertion that capital balances
  satisfy the G3 invariant at the moment of call. Raises
  CapitalInvariantViolation on breach. Returns None on success.

INV2 — Invariant equation (per G3, P7a):
  margin_available + margin_reserved + margin_used
    == cash_floor + min(0, realized_pnl_today)
  Tolerance: 0.01 (paise). Anything beyond -> violation.
  RATIONALE: profits don't add to tradable until T+1 settlement,
  but losses count immediately. Hence min(0, realized_pnl_today).

INV3 — Public API (single function):
  assert_capital_invariant(
    margin_available: float,
    margin_reserved: float,
    margin_used: float,
    cash_floor: float,
    realized_pnl_today: float,
    bucket: str = "global",      # for context
    mutation_type: str = "",     # for context (e.g. "reserve", "release")
    reservation_id: str = "",    # for context
    tolerance: float = 0.01,
  ) -> None
  Raises CapitalInvariantViolation with full context dict on breach.

INV4 — Context dict on violation (lock):
  {
    "bucket": str,
    "mutation_type": str,
    "reservation_id": str,
    "margin_available": float,
    "margin_reserved": float,
    "margin_used": float,
    "cash_floor": float,
    "realized_pnl_today": float,
    "lhs": float,           # available + reserved + used
    "rhs": float,           # cash_floor + min(0, realized_pnl)
    "delta": float,         # lhs - rhs
    "tolerance": float,
  }

INV5 — Helper functions (module-level, also exported):
  compute_lhs(available, reserved, used) -> float
  compute_rhs(cash_floor, realized_pnl_today) -> float
  compute_tradable_balance(cash_floor, realized_pnl_today) -> float
    Returns cash_floor + min(0, realized_pnl_today) per P7a.
  All pure functions, no side effects.

INV6 — Negative balance guards (additional defensive checks):
  Before invariant check, validate each balance is not
  catastrophically negative:
    if margin_available < -tolerance: raise (separate violation
      with mutation_type="NEGATIVE_AVAILABLE")
    if margin_reserved < -tolerance: raise (NEGATIVE_RESERVED)
    if margin_used < -tolerance: raise (NEGATIVE_USED)
    if cash_floor < -tolerance: raise (NEGATIVE_CASH_FLOOR)
  realized_pnl_today CAN be negative (losses) — no check.

INV7 — fund_manager refactor (mandatory):
  Remove the inline invariant check from fund_manager.py FM11.
  Replace with import + call to assert_capital_invariant.
  Behavior must remain identical — all 30 fund_manager tests
  must continue to pass without modification.
  This is the audit fix: single source of truth for invariant
  logic.

INV8 — Layer & deps:
  Layer 3 (capital/, depends on core only).
  Imports: stdlib only, core.exceptions
  (CapitalInvariantViolation).
  NO state_store, NO logger (caller logs after catching).
  NO config_loader (tolerance is parameter, not config —
  invariant tolerance is mathematical constant).

INV9 — Determinism:
  Same inputs -> same outcome (raise or return None).
  No randomness, no time, no I/O. Foundation Rule 1.1.
  Thread-safe by virtue of being pure.

INV10 — NOT in scope:
  - Recovery from violation (caller's responsibility)
  - Logging (caller logs after catching)
  - State persistence (caller's responsibility)
  - Broker drift detection (G1 reconciler — separate module)
