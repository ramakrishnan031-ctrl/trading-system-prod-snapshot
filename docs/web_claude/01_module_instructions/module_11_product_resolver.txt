DESIGN DECISIONS TO LOCK BEFORE BUILDING
================================================================

PR1 — Purpose:
  Single source of truth for translating semantic product
  intent -> broker-specific product code. Removes all
  hardcoded "MIS"/"CNC"/"CO" strings from the codebase.

PR2 — Semantic intents (broker-agnostic):
  - INTRADAY        (auto-square-off same day, leveraged)
  - DELIVERY        (overnight hold, full cash)
  - COVER_ORDER     (intraday with mandatory SL, higher leverage)
  - BRACKET_ORDER   (intraday with SL+TGT bracket — if supported)

PR3 — Broker mappings (from system_config.yaml product_map):
  Zerodha:
    INTRADAY      -> "MIS"
    DELIVERY      -> "CNC"
    COVER_ORDER   -> "CO"
    BRACKET_ORDER -> "BO"   (note: Zerodha discontinued BO;
                              resolver should raise
                              ProductNotSupportedError)
  Future brokers (AngelOne, etc.) added by extending YAML.

PR4 — API:
  from broker.product_resolver import ProductResolver

  resolver = ProductResolver(product_map: dict[str, dict[str, str]])
  resolver.resolve(intent: str, broker: str = "zerodha") -> str
    -> Returns broker-specific code.
    -> Raises ProductNotSupportedError if mapping missing
       OR mapping value is empty/null/None.
    -> Raises ValueError if intent not in PR2 list.

PR5 — Reverse lookup (for reconciler):
  resolver.intent_for(broker_code: str, broker: str = "zerodha")
    -> str (semantic intent)
  Used by order_reconciler when reading broker positions back —
  needs to know if "MIS" means INTRADAY in our taxonomy.
  Raises ValueError if code unknown.

PR6 — Validation at construction:
  __init__ validates that product_map dict has at least
  one broker entry. Each broker entry must be dict[str, str].
  Reject empty maps with ValueError at construction time.

PR7 — New exception class:
  ProductNotSupportedError(BrokerError, SEVERITY="ERROR")
  context: {intent, broker, available_intents}
  Add to core/exceptions.py.

PR8 — Schema extension:
  system_config.yaml needs product_map section (already
  stubbed per config_loader build). Verify schema in
  config_loader.py supports nested dict structure:
    product_map:
      zerodha:
        INTRADAY: "MIS"
        DELIVERY: "CNC"
        COVER_ORDER: "CO"
        BRACKET_ORDER: ""    # empty -> not supported

  If schema needs extension, update SystemConfig model first,
  re-run test_config_loader.py.

PR9 — Layer & deps:
  Layer 2 (broker/). Imports: stdlib only,
  core.exceptions (ProductNotSupportedError).
  No core.config_loader dependency (product_map dict
  injected by caller, same pattern as market_windows).

PR10 — No defaults inside resolver:
  If a mapping is missing in YAML, the system fails loud.
  No "well, MIS is probably right" fallback. Aligns with
  Project Rule 14 — No Silent Fallbacks.
