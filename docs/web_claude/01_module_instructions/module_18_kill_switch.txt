LOCK BEFORE BUILD:

KS1 — Purpose: System-wide trading halt mechanism.
  Three modes:
    SOFT_KILL — block new entries, allow exits and monitoring
    HARD_KILL — block ALL orders + attempt to cancel open broker
                orders (Project Rule 13)
    INACTIVE  — normal operation
  is_active(intent="entry") -> bool used by every order dispatch.

KS2 — State model:
  Single state: KillState enum {INACTIVE, SOFT_KILL, HARD_KILL}.
  Plus reason: str, triggered_at: datetime, triggered_by: str.
  Persisted in state_store kill_switch_state table (single-row,
  id=1) for restart recovery.

KS3 — Audit Issue #18 fix — startup recovery:
  On construction, READ state from state_store. If row exists
  and state != INACTIVE, log CRITICAL and remain in that state.
  DO NOT overwrite with INACTIVE on startup. Manual operator
  must call resume() to clear.
  Old bug: startup re-init overwrote operator's manual halt.

KS4 — Audit Issue #4 fix — deadlock prevention:
  Use threading.RLock (NOT Lock).
  soft_kill() and hard_kill() may call internal methods that
  re-acquire the lock. RLock allows reentrant acquisition by
  same thread. Original deadlock: record_api_failure() held
  Lock then called soft_kill() which tried to acquire same
  Lock -> freeze.

KS5 — Constructor:
  KillSwitch(

                                   #   succeeded: int, failed: list[str]}
  )

KS6 — Public API:
  is_active(intent: str = "entry") -> bool
    intent="entry" -> True if SOFT_KILL or HARD_KILL
    intent="exit"  -> True only if HARD_KILL
    intent="any"   -> True if either kill mode

  current_state() -> KillState (enum value)
  status() -> dict {state, reason, triggered_at, triggered_by}

  soft_kill(reason: str, triggered_by: str = "system") -> None
    Atomic: persist state -> publish event -> log CRITICAL.
    Idempotent: calling when already SOFT_KILL is no-op
    (logged DEBUG).
    Calling when HARD_KILL: ignored, log WARNING (cannot
    downgrade hard to soft).

  hard_kill(reason: str, triggered_by: str = "system")
    -> CancellationReport
    Atomic: persist state -> publish event -> log CRITICAL ->
    invoke on_hard_kill_cancel_fn() if provided ->
    return CancellationReport.
    Audit Project Rule 13: MUST attempt to cancel all known
    open orders. Failed cancellations -> CRITICAL alert via
    callback (handled inside on_hard_kill_cancel_fn).
    Idempotent: calling when already HARD_KILL re-runs
    cancellation attempt (in case orders re-appeared).

  resume(reason: str, resumed_by: str) -> None
    Manual operator action. Sets state to INACTIVE.
    Persists. Publishes event. Logs INFO with reason.
    Refuses if state already INACTIVE (raises ValueError).
    Triggered_by must be non-empty (audit trail).

  record_api_failure() -> None
    Internal counter. After N consecutive API failures
    (configurable, default 3), auto-trigger soft_kill().
    Counter resets on any successful API call (record_success()).
    This is the auto-trip mechanism.

  record_success() -> None
    Resets api_failure counter.
