RE4 — API:
  engine.approve(
    symbol,
    side,
    intent,
    sizing_result,        # SizingResult from position_sizer
    signal_id,
  ) -> ApprovalResult

  ApprovalResult (frozen dataclass):
    approved: bool
    reason: str               # human-readable
    failed_check: str         # which check rejected (or "")
    checks_run: list[str]     # all checks executed in order
    snapshot: dict            # capital + counts at decision time

RE5 — Check sequence (lock; ordered, short-circuit on first fail):
  1. KILL_SWITCH       — if active, reject immediately
  2. SIZING_VALID      — sizing_result.success must be True
  3. CAPITAL           — fund_manager bucket has margin_required
  4. OPEN_POSITIONS    — count(open) + count(in_flight) < max
  5. DAILY_TRADES      — count(today) < max_daily_trades
  6. CONSECUTIVE_LOSSES — recent loss streak < max_consecutive_losses
  7. DAILY_LOSS        — abs(daily_realized_pnl) < daily_loss_limit
  8. SECTOR_EXPOSURE   — current sector exposure + this trade
                          margin <= max_sector_exposure_pct * total
  9. DUPLICATE_SYMBOL  — no existing open or in-flight position
                          for same symbol
  Each check is a method: _check_X(...) returning (passed: bool,
  reason: str). approve() runs them in order.

RE6 — Audit Issue #6 fix — sector concentration race:
  SECTOR_EXPOSURE check counts BOTH open positions AND in-flight
  reservations (queried from state_store). Audit flaw was
  checking only open. In-flight = orders placed but not yet
  filled. state_store query: SUM(margin) WHERE
  status IN ('SUBMITTED','OPEN','PARTIAL') AND sector = ?

RE7 — Audit Issue #6 fix — daily loss intra-trade check:
  DAILY_LOSS check uses fund_manager.get_snapshot()
  .daily_realized_pnl. risk_engine does NOT track unrealized
  P&L (that's order_monitor's job during live position
  monitoring). risk_engine is a GATE, not a monitor.

RE8 — Kill switch integration:
