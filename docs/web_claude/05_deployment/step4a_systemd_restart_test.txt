"""
Temporary test harness for Step 4a.
Simulates a long-running service that:
  - Prints heartbeat (tests journal capture)
  - Handles SIGINT gracefully (tests clean stop)
  - Can be force-killed (tests Restart=on-failure)
Delete this file after Step 4a complete.
"""
import signal
import sys
import time
from datetime import datetime

_shutdown = False

def handle_sigint(signum, frame):
    global _shutdown
    print(f"[{datetime.now().isoformat()}] SIGINT received, "
          "shutting down cleanly")
    _shutdown = True

signal.signal(signal.SIGINT, handle_sigint)
signal.signal(signal.SIGTERM, handle_sigint)

print(f"[{datetime.now().isoformat()}] Harness started, PID={os.getpid() if (__import__('os')) else 'unknown'}")

import os
print(f"[{datetime.now().isoformat()}] Harness started, PID={os.getpid()}")
sys.stdout.flush()

tick = 0
while not _shutdown:
    tick += 1
    print(f"[{datetime.now().isoformat()}] heartbeat {tick}")
    sys.stdout.flush()
    # Small sleeps so SIGINT is responsive
    for _ in range(20):
        if _shutdown:
            break
        time.sleep(0.1)

print(f"[{datetime.now().isoformat()}] Clean exit (tick={tick})")
sys.stdout.flush()
sys.exit(0)
EOF

4a-E — SCENARIO 2: CRASH RESTART (Restart=on-failure)

  sleep 15

Expected: Active: active (running), new PID different from
old, "(Restarting X of 3)" not present (first restart, budget
still available).

Expected sequence:
  Started trading-system.service
  heartbeat entries
  Main process exited, code=killed, status=9/KILL
  (wait 10s)
  Started trading-system.service  (second start)
  new heartbeat entries

  # Stop cleanly
  sudo systemctl stop trading-system.service

4a-F — SCENARIO 3: RESTART BUDGET EXHAUSTION
================================================================

Per our unit: StartLimitIntervalSec=300, StartLimitBurst=3.
Three failures in 5 min -> systemd stops trying to restart.

Test: crash 3 times quickly.

  # Start + crash 3 times in rapid succession
  for i in 1 2 3; do
      sudo systemctl start trading-system.service
      sleep 2
      PID=$(systemctl show --property MainPID --value trading-system.service)
      echo "Crash attempt $i: PID=$PID"

Expected: "Active: failed" OR "Active: activating (auto-restart)"
that STAYS in that state until budget resets.

  sudo journalctl -u trading-system --since "2 minutes ago" --no-pager | grep -E "Start request|Failed|exceeded"

Expected: includes "Start request repeated too quickly" or
"Failed with result 'start-limit-hit'" after 3rd crash.

  # Reset to continue testing

  sudo systemctl stop trading-system.service

================================================================
TROUBLESHOOTING
================================================================

"Unknown key name 'KillSignal'":
  Unlikely; it's standard. Check: systemctl --version
  Should be >= 230.

Harness exits immediately:
  Check: journalctl -u trading-system -n 20
  Look for ImportError or Python syntax error.

"reset-failed" doesn't clear state:
  sudo systemctl daemon-reload
  Try again.

Journal disk usage very high:
  Normal for a VM with fresh journal. Not a concern.
  To limit: journalctl --vacuum-time=7d or edit
  /etc/systemd/journald.conf (not our scope).

Alert watcher doesn't cycle:
  Check: journalctl -u alert-watcher -n 20
  If stuck "activating": script has import error.
