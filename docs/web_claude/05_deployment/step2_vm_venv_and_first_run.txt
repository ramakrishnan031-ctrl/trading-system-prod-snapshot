Git Bash cannot reach Windows ssh-agent. All SSH commands must

================================================================
2A -- SECURE .env TRANSFER (PC -> VM)
================================================================

The .env file contains real credentials. NEVER commit it.
Transfer via SCP only.

First verify .env exists on PC:
  ls -la D:/Projects/trading-system/.env

Expected: approx 3341 bytes (5-account schema, real creds filled).

If missing or zero-byte: STOP. Tell Rama to fill it.

Confirm VM target directory exists:
  ssh trading-vm "ls -la ~/trading-system/"

Transfer .env:
  scp D:/Projects/trading-system/.env \
      trading-vm:/home/ubuntu/trading-system/.env

Verify on VM:
  ssh trading-vm "ls -la ~/trading-system/.env && wc -l ~/trading-system/.env"

Set strict permissions (owner-only read):
  ssh trading-vm "chmod 600 ~/trading-system/.env"

Verify permissions:
  ssh trading-vm "ls -la ~/trading-system/.env"
  # Expected: -rw------- 1 ubuntu ubuntu ... .env

================================================================
2B -- CREATE VENV ON VM
================================================================

SSH into VM and run:

  ssh trading-vm
  cd ~/trading-system

  # Ensure Python 3.14 is active
  python --version
  # Expected: Python 3.14.3

  # Create venv
  python -m venv venv

  # Activate and verify
  source venv/bin/activate
  python --version
  # Expected: Python 3.14.3 (from venv)
  which python
  # Expected: /home/ubuntu/trading-system/venv/bin/python

  # Upgrade pip
  pip install --upgrade pip setuptools wheel

2D -- AUTO-ACTIVATE VENV ON SSH LOGIN
================================================================

Append to ~/.bashrc on VM so venv activates automatically
when Rama SSHs in:

  cat >> ~/.bashrc << 'EOF'

# Auto-activate trading-system venv on login
if [ -f ~/trading-system/venv/bin/activate ]; then
    source ~/trading-system/venv/bin/activate
    cd ~/trading-system
fi
EOF

Test: exit SSH and reconnect:

  exit

Then:
  ssh trading-vm

On successful connect, prompt should show:
  (venv) ubuntu@trading-system:~/trading-system$

If venv doesn't auto-activate:
  - Check: ssh trading-vm "tail -20 ~/.bashrc"
  - Verify no syntax errors
  - Check: ssh trading-vm "ls ~/trading-system/venv/bin/activate"

  ARM wheel may be missing. Check:
    pip install --verbose kiteconnect
  If compilation fails, ensure build deps installed:
    sudo apt install python3.14-dev libffi-dev libssl-dev

  cd ~/trading-system
  ls tests/   # must have subfolders
  Ensure PYTHONPATH not set to something weird:
    unset PYTHONPATH
  Re-run.

Test failure: ImportError: cannot import X:
  pip install missing package manually
  Add to requirements.txt on PC, commit, push to regenerate

Test failure: no such file or directory: config/...:
  Git push may have missed a file. Verify:
    ssh trading-vm "ls config/"
  If missing, push again from PC.

  Check: .env loaded correctly?
    ssh trading-vm "source venv/bin/activate && \
      python -c 'import os; print(bool(os.environ.get(\"TELEGRAM_BOT_TOKEN\")))'"
  Should print True. If False, .env not loading.

Holiday guard doesn't trigger on Saturday:
  Check timezone: ssh trading-vm "timedatectl"
  Must show Asia/Kolkata.
  Check date: ssh trading-vm "date"
  Must show Saturday.
