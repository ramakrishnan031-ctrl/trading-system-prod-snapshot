IMPORTANT: SYSTEMD VS INTERACTIVE
================================================================

main.py has TWO modes:
  - Interactive (--interactive): prompts for account, mode, etc.
    Rama runs this Monday morning for first paper session.
  - Non-interactive (no flag): uses primary account from
    accounts.csv, reads existing token file, no prompts.
    This is what systemd will run.

Systemd will invoke:
  python main.py --mode paper
  (OR --mode live for live sessions — Rama's manual override
   when ready; default service is paper)

Systemd will NOT use --interactive. That defeats the purpose.

      Destination Port Range: 5000
      Description: Chartink webhook

  Flag this in your report — you cannot do it via SSH.

3B — SYSTEMD UNIT: trading-system.service
================================================================

Create unit file:
  sudo tee /etc/systemd/system/trading-system.service > /dev/null << 'EOF'
[Unit]
Description=Trading System v2 (paper/live mode)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=ubuntu
Group=ubuntu
WorkingDirectory=/home/ubuntu/trading-system
Environment="PATH=/home/ubuntu/trading-system/venv/bin:/usr/bin:/bin"
EnvironmentFile=/home/ubuntu/trading-system/.env

# Default mode: paper. To run live, use:
#   sudo systemctl edit trading-system
# and override ExecStart with --mode live
ExecStart=/home/ubuntu/trading-system/venv/bin/python \
    /home/ubuntu/trading-system/main.py --mode paper

# Send SIGINT on stop so main.py's Ctrl+C handler runs
# (clean shutdown, SHUTDOWN event, DB flush)
KillSignal=SIGINT
TimeoutStopSec=30

# Restart policy
Restart=on-failure
RestartSec=10
StartLimitIntervalSec=300
StartLimitBurst=3

# Logging to journal (journalctl -u trading-system)
StandardOutput=journal
StandardError=journal
SyslogIdentifier=trading-system

# Security hardening
NoNewPrivileges=true
ProtectSystem=full
ProtectHome=false
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF

Reload systemd:
  sudo systemctl daemon-reload

Verify unit loads cleanly:
  sudo systemctl status trading-system.service
  # Expected: loaded (not active yet; that's correct)

3C — SYSTEMD UNIT: alert-watcher.service
================================================================

alert_watcher.py checks sentinel files and sends critical
alerts. Separate service because:
  - Runs independently of main (even if main crashes,
    alerts still fire for failed sentinel clears)
  - Different restart policy (always-on, not just market hours)

Create unit file:
  sudo tee /etc/systemd/system/alert-watcher.service > /dev/null << 'EOF'
[Unit]
Description=Trading System - Alert Watcher (sentinel monitor)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=ubuntu
Group=ubuntu
WorkingDirectory=/home/ubuntu/trading-system
Environment="PATH=/home/ubuntu/trading-system/venv/bin:/usr/bin:/bin"
EnvironmentFile=/home/ubuntu/trading-system/.env
ExecStart=/home/ubuntu/trading-system/venv/bin/python \
    /home/ubuntu/trading-system/scripts/alert_watcher.py

KillSignal=SIGINT
TimeoutStopSec=10

Restart=always
RestartSec=10

StandardOutput=journal
StandardError=journal
SyslogIdentifier=alert-watcher

NoNewPrivileges=true
ProtectSystem=full
ProtectHome=false
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF

Reload:
  sudo systemctl daemon-reload

3D — CRON JOB: 05:00 IST TOKEN CLEANUP
================================================================

Each day at 05:00 IST, delete yesterday's Zerodha token so
system forces fresh login when operator runs zerodha_login.py
on PC + SCPs new token.

Edit crontab for ubuntu user:
  crontab -e

Add line:
  0 5 * * 1-5 rm -f /home/ubuntu/trading-system/data_store/session/zerodha_token.json

(1-5 = Monday-Friday. Cron uses system timezone, which is
 Asia/Kolkata as set in Step 1.)

Verify:
  crontab -l

Test cron entry syntax (dry-run; do not actually run the rm):
  systemctl status cron
  # Should be active

guard will block startup cleanly and systemd will record
"success" exit. That's fine to test once, but don't ENABLE

================================================================
TROUBLESHOOTING
================================================================

systemctl start fails with "Failed to start":
  sudo journalctl -u trading-system -n 50 --no-pager
  Look for ImportError, permission denied, or missing .env vars.

"EnvironmentFile=... not found":
  Verify: ls -la /home/ubuntu/trading-system/.env
  Permissions must allow service user (ubuntu) to read.

"Active: activating (auto-restart)" loop:
  Service crashes too fast. Check journal for real error.
  StartLimitBurst=3 means after 3 failures in 300s, systemd
  stops trying. Good.

Holiday guard doesn't fire:
  Check timezone on VM: timedatectl
  Must show Asia/Kolkata. If UTC, redo Step 1C.

ufw allow doesn't stick:
  sudo ufw status
  If disabled: sudo ufw enable
