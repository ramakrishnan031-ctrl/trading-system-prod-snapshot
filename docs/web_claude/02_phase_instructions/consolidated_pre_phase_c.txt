AUDIT 1 - "Pre-live audit" (10 high-level concerns)
----------------------------------------------------------------

# 1. State consistency risk (BIGGEST ISSUE)
Not strong guarantee: Order placement + state update = ATOMIC
Risk: order placed OK, DB update fails -> system loses track.
Fix: transaction(reserve, insert trade, insert order, COMMIT)
THEN place broker order. Reconciliation must fix mismatch.

# 2. Broker failure handling incomplete
zerodha_adapter.py, order_monitor.py likely don't fully handle:
- partial fills
- delayed fills
- rejected SL
- network retry edge cases
Missing: IF order status unknown -> reconcile immediately.
IF SL missing -> HALT SYSTEM.

# 3. Reconciliation robustness unclear
6-case reconciliation (G1) especially:
- orphan broker position
- partial quantity mismatch
- orphan open orders
Non-negotiable for live. Weak -> lose money silently.

# 4. Crash recovery risk
On restart: rebuild state ONLY from broker?
Required: Broker = source of truth ALWAYS.

# 5. Concurrency + SQLite risk
Multi-thread + SQLite. Risks: multiple writes, long
transactions, deadlocks.
Must verify: WAL mode ON, short transactions, no nested
transactions.

# 6. Order lifecycle correctness
Does order_state_machine enforce: Only ONE exit path
(SL OR TGT never both)?
If not: Double execution = loss.

# 7. Kill switch enforcement
ALL modules respect it BEFORE action?
Especially order placement + signal processing.

# 8. Signal dedup (P6) enforcement
Must be enforced at DB level (UNIQUE index).
Only in Python -> race condition -> duplicate trades.

# 9. Logging + traceability
Every log must include signal_id, trade_id, order_id.

# 10. No chaos testing yet
Haven't tested:
- broker API failure
- network timeout
- partial fills
- restart mid-trade

Minimum test checklist before live:
1. Order flow: entry success, entry reject, partial fill,
   timeout cancel
2. Exit flow: SL hit, TGT hit, cancel failure
3. Crash scenarios: crash after entry, crash before SL,
   restart recovery
4. Reconciliation: manual close in broker, orphan order,
   mismatch qty
5. Capital: multiple trades, loss sequence, T+1 behavior

Medium issues: EventBus usage minimal (G9), Config validation
fail-fast, Rate limiter per endpoint, CRITICAL alerts always
delivered.

DO NOT go live yet. Paper trade 5-7 days -> inject failures
manually -> fix inconsistencies -> live with small capital only.

AUDIT 2 - "Second pass" (30 concrete issues)
----------------------------------------------------------------

CRITICAL:

# 1. State consistency (repeated from Audit 1)

# 2. Race condition in order_placer.py line 147-151:
fill_map accessed without lock in _on_order_filled.
_fill_map written in place() with lock, but _on_order_filled
runs in order_monitor thread -> race with place() completion.
Window small but exists.

# 3. Incomplete ATR/Sector Implementation:
step_executor returns 0.5 for missing sector/ATR (neutral
score). _derive_prices warns but falls back to FIXED_PCT for
ATR. DANGEROUS - ATR strategies silently degrade without alert.

# 4. Missing Quote Provider in Paper Mode:
zerodha_adapter.py requires quote_provider for paper mode
get_quote(). main.py does NOT inject a quote provider. Paper
mode get_quote() will raise NotImplementedError and crash.
[FIXED IN PHASE B]

# 5. StateStore Schema Version Mismatch Risk:
EXPECTED_SCHEMA_VERSION = 8. No migration logic. If old DB
exists, startup crashes with SchemaVersionMismatch.

# 6. Missing quote_fn for SmartTgtManager:
main.py passes broker_adapter.get_quote. quote_fn required for
startup LTP check; if missing, only warning logged.

# 7. OrderMonitor on_orphan_callback Type Mismatch:
_make_orphan_cb calls kill_switch.soft_kill() missing
triggered_by parameter.
[ALREADY FIXED per Phase A triage]

# 8. _make_critical_failure_cb Same Issue:
Returns _on_critical_failure(source, reason) but
kill_switch.soft_kill() needs triggered_by.
[ALREADY FIXED per Phase A triage]

# 9. WebhookReceiver in_flight Symbol Never Released on Some
Paths:
signal_processor releases in finally block (good). But if
signal_processor crashes before finally, symbol stuck in
in_flight. No timeout mechanism.

# 10. Missing order_reconciler.broker_orders_fn:
main.py passes None. CHECK 6 (ORPHAN_ORDER) will never run.
Open orders not reconciled.
[FIXED IN PHASE B]
