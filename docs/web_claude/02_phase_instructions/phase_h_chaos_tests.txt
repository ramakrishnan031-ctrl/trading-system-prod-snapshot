  - No lost capital

  - Reconciliation cleans up on restart

CHAOS SCENARIOS (CX4-CX12)
================================================================

CX4 — SCENARIO 1: Process crashes between place_order success
       and state update
  Setup:
    1. Seed system with pending signal through to sizing
    2. Configure SimKite to return success on place_order
    3. Mock state_store.update_order_placed to raise
       RuntimeError
  Expected:
    - Broker shows order (via SimKite script)
    - Local state missing order update
    - Reconciler detects ORPHAN_ORDER on next cycle
    - Reconciler action: cancel the orphan OR write local
      record (per G1 policy)
    - No duplicate placement on retry
    - Capital reservation released or recovered correctly

CX5 — SCENARIO 2: Broker place_order network timeout
  Setup:
    1. Seed system with signal
    2. SimKite.delay_next_place_order(60) -> triggers adapter
       timeout at configured read_sec
  Expected:
    - adapter raises BrokerTimeoutError
    - order_placer catches, releases reservation
    - signal marked PLACEMENT_FAILED
    - No partial state (no orders row with PENDING stuck)
    - Kill switch NOT triggered (single timeout not catastrophic)
    - After 3 consecutive timeouts: kill switch fires

CX6 — SCENARIO 3: SimKite returns "status unknown" for order
  Setup:
    1. Place order successfully
    2. SimKite.script_status_unknown(order_id) for next N polls
  Expected:
    - order_monitor handles empty/unknown status per Phase B
      fix (BLOCKER #8)
    - After N consecutive unknowns: orphan detection fires
    - on_orphan_callback triggers soft_kill

CX7 — SCENARIO 4: Partial fill then rejection of remaining qty
  Setup:
    1. Place entry for qty=100
    2. SimKite scripts partial fill (60 filled, 40 pending)
    3. Then SimKite rejects remaining 40
  Expected:
    - Trade moves to PARTIAL status
    - SL and TGT orders placed for 60 (not 100)
    - Capital committed for 60 only
    - Rejected 40 logged, no retry attempt

CX8 — SCENARIO 5: Both SL and TGT complete simultaneously
       (LIMIT_TRIPLE race)
  Setup:
    1. Place LIMIT_TRIPLE order (entry + SL + TGT)
    2. Entry fills
    3. SimKite returns COMPLETE for BOTH SL and TGT on same
       poll cycle
  Expected:
    - System detects double-exit condition
    - Reconciler or order_monitor flags CRITICAL
    - Kill switch fires
    - No double capital release
    - Trade marked with special status (DOUBLE_EXIT or similar)
    - Operator alert sent

CX9 — SCENARIO 6: Quote feed dies mid-trail
  Setup:
    1. Active SmartTgt trail position
    2. SimKite.raise_on_quote raises for 3 consecutive polls
  Expected:
    - smart_tgt logs WARNING, skips trail that cycle
    - No modify_order call with stale data
    - After 3 failures: appropriate log level (not kill switch —
      quote feed hiccups are transient)
    - When quotes resume: trail catches up via
      recompute-on-reconnect path (G6)

CX10 — SCENARIO 7: Kill switch activates while signal
        in-flight
  Setup:
    1. Signal enters pipeline at screening stage
    2. Mid-screening: kill_switch.hard_kill()
    3. Pipeline continues to sizing, risk engine
  Expected:
    - Risk engine CHECK 1 (kill switch) rejects the signal
    - OR last-mile check in order_placer rejects
    - Signal marked REJECTED_KILL_SWITCH
    - No broker order placed
    - Capital never reserved

CX11 — SCENARIO 8: SQLite database locked during mutation
  Setup:
    1. Hold write transaction in test thread
    2. Attempt signal processing from worker thread
    3. Release after 3 seconds
  Expected:
    - Worker waits (WAL mode + BEGIN IMMEDIATE)
    - OR gets sqlite3.OperationalError
    - If error: handled gracefully, retry or signal
      REJECTED_DB_LOCKED
    - No partial transactions committed

CX12 — SCENARIO 9: Restart with pending broker order
  Setup:
    1. Fresh state_store
    2. SimKite pre-seeded with 1 open order for RELIANCE
       (simulates orphan left by prior crashed run)
    3. Start system
  Expected:
    - startup scenario detected (CRASH based on no SHUTDOWN event)
    - Reconciler synchronous pass finds broker order not in
      local state
    - CHECK 6 ORPHAN_ORDER action per G1
    - Either: cancel the orphan OR adopt into local state
    - Log CRITICAL + operator alert
